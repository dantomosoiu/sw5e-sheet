# Class abilities audit (adversarial player panel)

_2026-10-16. Five agents each played two SW5E classes level 1→20 across every archetype, as optimising players, and listed what they need from the extension; five verifier agents checked every claim against `dev/dumps/rules.json` and the code. 251 needs survived verification (174 confirmed as written, 42 corrected, 35 added by verifiers, none rejected)._

_Status columns reflect the code the panel read (before the class-choice commits of the same day). The "Shared mechanisms" table says what has been built since._

## Findings about sw5e.com itself

- **No structured data or builder UI for class option lists** (Discoveries, Exploits, Instincts, Strategies, Auras, Vows, Routines, Ideals, Force-Empowered Castings, archetype lists such as Engineer modifications). They exist only as markdown in class/archetype text; counts are class-table columns.
- **Maneuvers capped** by the builder at the table's "Maneuvers Known"; extra maneuvers (Malleable Maneuvering, Maneuver Strategist, Superiority Style) can't be recorded.
- **Feature data is stale/incomplete:** 101 class/archetype features filed only at their last level (Monk Focus at 11, Guardian Aura at 9, Scholar Sage Advice at 13), 113 missing entirely (most archetype capstones), some misattributed between archetypes.
- **No feature has usage data**, so the engine never reports uses.
- **Engine gaps:** superiority is `false` for Scholar and most Fighters (it reads old column names); class/archetype weapon, armor and tool proficiencies in prose are not applied (e.g. Scholar martial finesse vibroweapons: Chakram +4 instead of +6); archetype passives and capstone ability increases are not applied.
- sw5e.com **keeps unknown fields** in the character JSON (tested), so the extension can store its own data inside the character.
